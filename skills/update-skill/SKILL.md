# スキルの正本を改善する

正本は **ai-dev-kit リポジトリの `skills/`**。アプリの導入コピー、`.claude/skills/`、`.agents/skills/`、`.codex/skills/`、plugin キャッシュを直接編集・同期しない。使っただけで自動更新しない。

## 正本を特定する

1. 対象スキル名、改善したい挙動、具体例を会話から確認する。既に改善と編集を依頼されていれば許可を聞き直さない。
2. 作業中のリポジトリを正本と決めつけず、ai-dev-kit の checkout と `skills/`、manifest、remote を確認する。導入コピーから実行していて正本が見つからなければ、その所在だけを確認する。勝手に clone や別の正本作成をしない。
3. 正本の対象ファイルと関連参照、既存差分、適用規約を読む。対象外の変更を保全し、今回の改善範囲を確定する。

## 改善する

ホストに対応した公式 `skill-creator` が利用可能なら、[公式の改善手順](references/providers.md) を読み、正本の絶対パスと依頼範囲を渡して優先する。未導入なら次で完結し、勝手にインストールしない。

- 直前の失敗や具体的な使用例から、曖昧な条件・不要な手順・対象外の起動を絞る。一度の例を全作業の絶対ルールに広げない。
- 起動条件と重要な不変条件を短く本文に残し、条件付きの詳細は同じスキル配下の参照へ置く。単体インストールで必要な参照がそろうようにする。
- 記述ルールを変更する場合は `skills/output-style/references/output-*.md` を編集し、リポジトリ直下で `python scripts/sync-output-rules.py` を実行して各スキルの同梱コピーを更新する。`python scripts/sync-output-rules.py --check` で一致を確認する。
- 承認済みの範囲を編集し、frontmatter、内部リンク、導入単位の自己完結性、他スキルとの権限・停止条件の整合性を確認する。挙動が変わる場合は適切な使用例で判断を点検する。

変更箇所、改善理由、実施した検証、未確認事項を報告する。commit・push・tag・公開・導入先更新はこのスキルに含めず、別途依頼された場合だけ行う。配布が必要なら正本の変更を `release-kit` 等のリリース手順へ引き継ぐ。

## 記述ルール

記述・編集前に[共通ルール](references/output-common.md)を読み、出力内容に応じて[応答](references/output-response.md)・[ドキュメント](references/output-document.md)・[コード](references/output-code.md)の該当ルールを読む。チャット内の仕様書もドキュメントとして扱い、複数対象があれば各部分に適用する。ユーザー指定・リポジトリ規約・必要なテンプレートを尊重する。

更新結果は応答、SKILL.mdと参照文書はドキュメント、補助スクリプトはコードとして扱う。

提出前に、不要な説明・反復・装飾と、過去案への打ち消しを確認する。必要な条件・根拠・不確実性・挙動を保持し、コード変更には変更に応じた動作確認を行う。

## 研修モード

「研修モード」が明示された場合だけ、タスクの最後に良かった点・使いにくかった点・改善提案・今すぐ追加更新するかを1回確認する。そこから自動で自己更新を繰り返さない。通常は振り返り質問を出さない。

同じタスクで複数スキルを使っても、振り返りは全体の終了時に1回だけ行い、途中や各スキルの終了ごとに繰り返さない。
