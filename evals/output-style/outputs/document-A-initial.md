# 取得ジョブの運用手順

## 実行条件

Windows Task Schedulerが毎平日（月〜金）8:30 JSTに取得ジョブを実行します。祝日も月〜金であれば実行します。取得元APIは読み取り専用で、タイムアウトは60秒です。

ログは `logs/fetch-YYYYMMDD.log` に保存します。`YYYYMMDD` は実行日の年月日です。

## 実行前の確認

- 本番DBへの書き込みは禁止です。
- 同じ取得ジョブを同時に実行しないでください。手動実行前に、実行中のジョブがないことを確認します。
- APIの上限は1回500件です。600件を取得する場合は、各回500件以下になるよう入力を分割します（例：500件と100件）。

## 定期実行の確認

1. Windowsの「タスク スケジューラ」を開き、取得ジョブの登録タスクを選びます。
2. 実行状況と、当日の `logs/fetch-YYYYMMDD.log` を確認します。
3. 失敗している場合は、次の手順で担当者が対応します。

## 失敗時の対応と手動再実行

1. 当日のログを開き、失敗理由と取得済みの範囲を確認します。
2. 原因を解消し、再実行する入力範囲を確認します。再試行で重複取得しないことは未検証のため、取得済みの範囲が分からない場合は、確認できるまで再実行を保留します。
3. 同じジョブが実行中でないことを確認します。
4. タスク スケジューラで取得ジョブを選び、「実行」を選択します。分割した入力は、前の実行が終了してから次を実行します。
5. 実行後、当日のログで処理結果を確認します。

## 運用開始前に確認が必要な情報

登録タスク名、入力の指定・分割方法、ログフォルダの絶対パス、成功を判定するログの記載は、提供された情報では不明です。担当者が迷わず実行できるよう、これらを確定して本手順に追記してください。

# コミットメッセージ草案

平日朝のAPI取得ジョブと運用手順を追加

CSVの手動コピーから、Windows Task Schedulerによる毎平日8:30 JSTのAPI取得へ変更する。祝日も平日なら実行し、タイムアウトを60秒、ログ出力先をlogs/fetch-YYYYMMDD.logとする。失敗時は担当者がログを確認して手動再実行する。

前案の管理画面は取りやめ、Pullによる自動更新は導入しない。

本番DBへの書き込みと同一ジョブの同時実行を禁止する。API上限の500件を超える入力は分割する。再試行時の重複取得防止は未検証として運用手順に明記する。

元メモの「正本の証跡から整合性を担保し運用の解像度を上げる」という意図は、取得結果と失敗理由をログで確認できる手順として具体化する。整合性や重複取得防止の検証完了を意味するものではない。
