# README：取得ジョブの運用

## 実行条件

取得ジョブはWindows Task Schedulerから毎平日（月〜金）8:30 JSTに実行します。祝日も月〜金であれば実行します。

取得元APIは読み取り専用です。タイムアウトは60秒で、ログは `logs/fetch-YYYYMMDD.log` に保存します。

## 運用上の制限

- 本番DBに書き込まないでください。
- 同じジョブを同時に実行しないでください。手動再実行時も、同じジョブが実行中でないことを確認します。
- API上限は500件／回です。600件の入力は、500件と100件など、各回500件以下に分割して実行します。

## 失敗時の対応

1. 担当者が該当日の `logs/fetch-YYYYMMDD.log` を確認します。
2. 同じジョブが実行中でないことを確認し、担当者が手動で再実行します。

再試行で重複取得しないことは未検証です。

## 実行に必要な確認事項

以下は提供情報に含まれていないため、運用に使う前に確認が必要です。

- 登録タスク名と手動再実行の操作方法
- 入力の指定方法と分割方法
- ログの保存先を特定するための基準フォルダと日付の扱い
- 成功・失敗を判定するログの記載

# 別記：コミットメッセージ草案

平日8:30のAPI取得ジョブと運用手順を追加

CSVの手動コピーから、Windows Task Schedulerによる平日8:30 JSTのAPI取得へ変更する。祝日も平日なら実行する。前案の管理画面は取りやめ、Pullによる自動更新は導入しない。

タイムアウトを60秒とし、logs/fetch-YYYYMMDD.logにログを保存する。失敗時は担当者がログを確認して手動再実行する。

本番DBへの書き込み禁止、同一ジョブの同時実行禁止、API上限500件／回に応じた入力分割を運用手順に記載する。再試行時の重複取得防止は未検証として明記する。
